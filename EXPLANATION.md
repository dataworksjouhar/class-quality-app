# Class Quality Assessor: approach, results, limits

**Approach.** A QA reviewer has two minutes, so the app returns a label, timestamped evidence and the minutes worth watching. It measures first and judges second. An Observer (Gemini, audio plus one still per minute, 10-minute chunks) logs facts only: questions, answers, every student turn, feedback, board work, technical problems. Code computes the metrics. A text-only Judge scores five rubric areas, each citing event IDs that code checks; setup (area F), the label rule and confidence are code. The Judge never hears the audio, so accent, language and microphone quality cannot sway it. Names are redacted in code, and a leak test blocks any report that still contains one. An ffmpeg check reports recording quality separately from teaching. No processing service was named, so recordings go to Gemini on a paid tier, inline, with store=false; the README documents retention.

**What worked.** Timestamps match the transcripts within a second. One class got identical scores in three runs. The English and Malayalam demos got the same label, and a native speaker confirmed the Malayalam evidence. No names appeared in any report. A single run takes 6-8 minutes and costs $0.30-0.60.

**What failed.** Accuracy: on eight labelled classes the app matched 2 exactly and 7 within one level, against 2 and 6 for always answering "Good". It never gave Excellent or Poor. Reweighting the rubric areas was simulated and rejected. The Observer under-logged student talk until a turn list was added, and its audio ratings almost never flagged problems; the crackle in one quality-issue recording went undetected.

**Limitations.** Twelve samples, with rubric anchors written from feedback on the same recordings. The Judge always finds improvements and does not know the class type. A phone that sleeps mid-run loses the result. No tuning round was run; prompts stay frozen as evaluated.
