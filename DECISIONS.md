# Decisions log

Each line: decision, reason. Add new lines as decisions change. Never delete old ones; mark them "replaced by Dn".

- D1 Host: Streamlit Community Cloud. HF Spaces now needs a paid plan for compute Spaces. Drive link is the main input (streams to disk); upload is for small files only, because st.file_uploader holds the whole file in memory.
- D2 Tech issues: gate. Teaching is graded from usable minutes only; more than ~20% unusable means confidence Low and "needs human review".
- D3 Frames: decided after E2 (one recording with frames vs without).
- D4 Observer: 10-min chunks, 30 s overlap, parallel, inline only. Each chunk keeps only events in its own 10-min window. The Observer logs facts with absolute start times. Wait time and question-to-answer links are computed in code on the merged log (gap capped at 60 s).
- D5 Gemini privacy: Interactions API with store=false in one wrapper, no Files API, SDK and model pinned. README states the 55-day abuse-monitoring retention and names the host as a second processor.
- D6 Participation measured per 10 minutes and per student, not by headcount (1:1 classes exist).
- D7 Upload limit 200 MB (server.maxUploadSize), not the ~500 MB in the brief. st.file_uploader keeps the whole file in memory (see D1) and Community Cloud has about 2.7 GB RAM shared by all sessions. Full classes go through the Drive link.
- D8 Drive intake: a headers-only preflight to drive.usercontent.google.com catches restricted (sign-in redirect), missing (404) and quota-blocked files and files over 1 GB before downloading. gdown then runs as a subprocess with --no-cookies (never acts as anyone's Google account); a watchdog kills it above 1 GB or after 30 min.
- D9 One ffmpeg decode does everything: writes the Observer audio (AAC mono 16 kHz 32k, measured 13.4 MB/h), runs ebur128 for LUFS/LRA/true peak, and pipes native-rate PCM to numpy for clipping, silence and dropouts. The video is deleted right after. Frames are not extracted yet (D3 pending); when they are, they go in this same pass, before the delete.
- D10 Probing parses `ffmpeg -i` output instead of ffprobe, so the pip binary (imageio-ffmpeg, no ffprobe) works locally; Streamlit Cloud gets system ffmpeg from packages.txt.
- D11 Inventory and scripts label recordings <folder>-<n> and never print file names (they can contain teacher names). VTT and video stems do not match, so each video is paired with the VTT whose last cue ends closest to its duration; the gap is printed as a check.
- D12 E5 recording-quality calibration (the one allowed adjustment). On the 12 recordings, whole-file loudness is -16 to -20 LUFS everywhere (Zoom seems to normalise), so "much quieter" in quality issue-1 is not visible to any ffmpeg measure we tried (LUFS, per-minute level, channel balance; the files are dual-mono). Clipping happens in short bursts in every folder (excellent-1 has 91 s at full scale), so clipping is now listed with timestamps and is an issue only when dense (10+ clipped seconds in one minute; none of the 12). The digital-zero dropout detector found nothing in 10.5 h and was removed. What does separate: the number of 20+ s silent gaps (quality issue-2: 20/h; all others <= 15/h) and absent audio (< -70 dBFS for 60+ s) after the start (good-1: 9.7 min). Absent audio from 0:00 is the waiting room and is reported as "Audio starts at", not counted. Result: flags quality issue-2 and good-1; misses quality issue-1. The voice cracking around 1:03:00 in quality issue-2 is not clipping; the flag fires on that file for its gaps, not its cracking. Distortion detection without AI stays a known limitation.
